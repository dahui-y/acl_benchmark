# C 的第一轮：零 GPU 的阳性对照，结果是阴性

日期 2026-08-07。

**要回答的问题**：把高分辨率输出下采样回基图分辨率、比对基图——
这个量能不能定位"模型幻觉出来的物体"？

**为什么先做这个**：这条线上三篇论文（Pixelsmith / HiWave / ResDiT）
跨两种架构、两种范式，**全部退回人工评测**。HiWave 自己给了收据——
Fig.9 里有幻影的那张 ImageReward 0.0443，干净的那张 0.0168，**更差的赢了**。
我们没有标注员，所以必须自己造一个自动的量。
**而在写指标之前，先证明它在一个已知失效上会响——这是阳性对照纪律。**

---

## 做了什么

从 HiWave 的 PDF 抽出全部 18 张图，找到唯一同时给出
**基图 + 有幻影的输出** 的一张：**Fig. 11**（`p14_1_Im13.jpg`, 1037×1233）。

四格，切成 4 张 500×500（`panels/`）：

| 格 | 内容 | 期望 |
|---|---|---|
| `base_sdxl` | SDXL 1024²，两个苹果 | — |
| `hiwave` | HiWave 完整方法，干净 | 检测器**不许报警** |
| `lowfreq_guid` | 只引导低频，**凭空多两个悬浮苹果** | 检测器**必须报警，且位置对** |
| `hiwave_no_dwt` | 去掉 DWT，**同样两个悬浮苹果** | 同上 |

`detect.py` v0：逐窗口 z-score 后做归一化互相关（NCC），
`1 − NCC` 当作不相似度。z-score 的用意是让"只是变亮/变对比"的窗口得 1.0，
只有**结构**变化才动分。平坦窗口标 NaN 不参与——
这是上一轮 `sheet.py` 踩过的坑（平坦内容本来就没有可保留的东西）。

## 结果

```
output                       meanD    p95D   >thr%   top blobs
fig11_base_sdxl             -0.000   0.000     0.0   -            ← 自比，健全性通过
fig11_hiwave                 0.021   0.076     0.1   (2, 0.82)
fig11_lowfreq_guid           0.113   0.322     3.8   (49, 0.58) (15, 0.62) (11, 0.53)
fig11_hiwave_no_dwt          0.111   0.325     4.0   (49, 0.55) (23, 0.61) (14, 0.52)
```

**数字分开了**：meanD 5.4×，超阈面积 40×。

**但热图证明分开的原因是错的。** 最强响应落在
**窗棂和窗帘的边缘**——两个失败变体不只多长了苹果，
**整个窗户和窗帘被重画了**。最大的 blob（49 cells）是漂移，不是苹果。

加了色度通道复测（`maps/gray_vs_chroma.png`）：**更差**。
底图本身（木框 vs 窗外绿树）色度结构就强，轻微位移满图报警，
**包括没有幻影的 HiWave 那一行**。

> **判定：v0 阴性。它测的是"画面变没变"，不是"有没有幻觉出物体"。**
> 一个不长幻影但把窗帘重画一遍的方法，会拿到同样的坏分。

## 这一轮真正的收获（三条）

1. **设计要求被钉死了**：这个量必须能把
   **(a) 长出新物体** 与 **(b) 全局构图漂移** 分开。
   这不再是"以后可能要注意的事"，是**已经用实验证明会失效的地方**。
   朴素的结构相似度和色度差**都做不到**。

2. **论文的图供不出干净的阳性对照。** 18 张全部盘点：

   | 类型 | 图 | 可用性 |
   |---|---|---|
   | 有基图 + 有幻影 | **只有 Fig. 11** | ⚠️ 被漂移污染 |
   | 有幻影、无基图 | Fig. 2a / 7 / 9 / 17 | ❌ 检测器要基图 |
   | 有基图、无幻影 | Fig. 5 / 10 / 16 | ✅ 只能当阴性 |

   Fig.7 是 `HiDiffusion | Pixelsmith | HiWave`，Fig.17 是 `Pixelsmith | HiWave`——
   **两张都没有 SDXL 基图那一列。**

3. **Fig. 11 是"困难版"，不是"真实版"。**
   我们真正要测的对照是 `SDXL 基图` vs `Pixelsmith`——两者**都声称保持构图**，
   漂移应当远小于这个消融。**但这是推断，不是已知。**
   在拿到真实配对之前，不能拿它当 v0 失败的解释。

---

## 下一步：这一步开始必须用 GPU

零 GPU 的路走完了。要拿到干净的阳性对照，只能自己造：

1. 跑 Pixelsmith（代码已在 `help_code/Pixelsmith/`，SDXL fp16 已就位，
   原文 7.4 GB 显存），**同 seed 出 1024² 基图 + 4096² 输出**
2. HiWave 说 Pixelsmith *"frequently suffers from object duplication"*，
   所以几十条 prompt 内应该能撞到。**撞到的那几张就是阳性对照。**
3. 在真实配对上重跑 v0 —— 如果漂移确实小得多，v0 可能就够；
   如果还是分不开，就按第 1 条的要求重新设计
4. 阴性对照用同样的配对：HiWave 论文 Fig.5/10/16 那类
   "只是细节增强"的情形，检测器必须安静

**没有阳性对照的阴性结果不能用。反过来也一样——
没有在真实配对上通过阳性对照之前，这个量不能叫指标。**
