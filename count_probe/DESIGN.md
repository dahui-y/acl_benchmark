# DESIGN —— 检测修正器（方向 c）· 预登记（2026-08-21）

本文档在跑任何 GPU 实验**之前**写死设计、标定预算与生死判据。依据全部来自
FINDINGS.md 与 Phase 0/B 的一手读数。**改判据必须在本文件留痕并说明理由。**

## 1. 方法（纯删除原型，Phase C = correct_batch.py）

vanilla SDXL 生成 → YOLOv8x 数目标类 → 多出 k 个则删分数最低的 k 个框
（并列取小面积）→ 框膨胀 24px 成 mask → base SDXL 遮罩重去噪
（diffusers SDXLInpaintPipeline，4 通道 UNet 逐步 latent 混合 = RePaint 式）
→ 像素级贴回（mask 外原像素，羽化 8px）→ 重检测，仍多则再来一轮（≤2 轮）。

零训练部件、零新权重、零 LLM、无梯度图。与两位在位者的机制区别：
CountGen 靠注意力梯度引导（已证伪：评测集净 0，迭代空转）；
SLD 靠 GPT-4 控制器 + GLIGEN 训练权重 + 自修自评（OWLv2 修 OWLv2 评）。

## 2. 立项依据（全部一手，出处见 FINDINGS.md）

- 换算率之门（见数前定 80%）：**P(v9e=N | v8x=N) = 85.7%**（n=70，vanilla）。
  ⚠️ 第一次门检误用了边缘一致率（66.5%）并宣判死亡 —— 修正环只在"宣布够数"
  时需要评测器点头。两次判定的阈值都在见数前预登记。
- 头寸（v8x 视角，167 题）：不动 70 / 要删 70 / 要补 27。删除主导。
- 盈亏平衡：不动题贡献 ≈60，要补题 ≈+3，故
  **打平 CountGen(95 题)：p_del × t_edit ≥ 0.46；+10 分(112 题)：≥ 0.70**
  （p_del = 环内删除成功率；t_edit = 编辑图上的评测器确认率，≤85.7%）。
- 改坏通道上限：v9e 对而 v8x 错的 7 题会被误编辑，预期损失 1~2 题。

## 3. 标定预算（超出即调参违纪）

    strength ∈ {0.8, 1.0} × prompt-mode ∈ {ctx, bg}   —— 共 4 个配置

## 4. 生死判据（原型级，tune2 上）

记 tune2 上"v8x 说要删"的题集 D：

- **活**：最优配置在 D 上环内删除成功率 p_del ≥ 0.6，且整批相对同批 CountGen
  的配对 McNemar 方向为正；画质红线（相对 CountGen 逐张配对：colourfulness
  中位 ≈0、无色张数不升、CLIPScore 均值不降超过 0.3）不破。
  → 进入评测集（一次），并再议补缺失操作。
- **死**：四个配置的 p_del 全部 < 0.5，或画质红线全破。
  → **方向 c 终结，不再有第三种机制**（复活牌已用过一次且有据；再翻案即自欺），
  转诊断/评测协议论文。
- 中间地带：p_del ∈ [0.5, 0.6) → 只允许分析失败案例并写明原因，不允许扫新旋钮；
  若失败集中于可命名的单一机制（如洞里重新长出目标类），允许**一个**针对性
  修改再测一轮，须先在本文件登记。

## 5. 评测协议（防循环性，三重）

1. 主口径：YOLOv9e（基准惯例），与 CountGen 同一评测链、配对 McNemar。
2. 第三方：OWLv2 对两臂同测（绝对值噪，两臂差值有意义）。
3. 作者盲数：主对比子集上盲法人工计数（计数是客观量；披露作者自评 + 盲法 +
   n + 检验方法）。环内 v8x 与评测器 v9e 的家族重叠必须在文中披露。

## 5.5 实现修正留痕（不计入标定预算）

界线：**判据是「实现有没有兑现本文件写下的设计意图」，不是「指标好不好看」。**
兑现意图的修改 = 实现修正，必须在此登记；为了分数去扫某个旋钮 = 调参违纪。

- **2026-08-21 · mask 吃邻居（build_mask 挖回保留框）**
  冒烟实测：`apple_num=7`，v8x 初检 15，按设计删分数最低的 8 个框，实际落到 4
  —— 多掉 3 个。原因：dilate=24 让待删框的 mask 盖住了密集场景里的邻居
  （即第 6 节风险 #3 的实测显形）。§1 写的是「删多出的 k 个」，实现没兑现。
  修法：删除 mask = 膨胀后的待删框之并 **减去** 保留框（保留框不膨胀，
  允许其边缘被重画，主体像素受保护）。dilate 仍是 24，未扫。
  同时在 counter_log 增加 `want`（该轮想删几个）与 `mask_frac`（mask 占比），
  使「意图 vs 实际」逐轮可见 —— 下次再背离不必靠肉眼发现。

## 5.6 中间地带的候选补救（见 tune2 成绩**之前**登记，只许选其一）

§4 允许 p_del ∈ [0.5,0.6) 时做**一个**针对性修改。为免事后现编理由，先把
候选写死在这里；届时只许从下面二选一，且必须说明失败集中于哪一条机制。

冒烟已经指出唯一可命名的失败机制：**密集簇里 k 大时，轴对齐框 mask 表达不出
"删这 k 个、不碰那 n−k 个"**（apple N=7、初检 15、k=8：挖回保留框后 mask 只剩
3.2% 的缝隙，重去噪等于没做，第二轮还在缝里长出一个 → 15→15→16）。

- 候选 A：**无进展即停**。一轮后计数没下降就不再进第二轮。只影响已经失败的
  题，作用是止损（阻断 15→16 这类漂移），不提高任何题的成功率。
- 候选 B：**按几何可行性限每轮 k**。只删"挖回保留框后仍保有自身面积 ≥50%"
  的框，剩下的留给下一轮。不改删除选择规则的排序（仍是低分优先、并列取小），
  只改一轮里取几个。

不在候选里（越界，需另起预登记）：换像素级分割 mask（引入 SAM 等新部件，
破坏"零新权重"）、扫 dilate/feather、改删除排序规则。

## 5.7 判据修改（2026-08-21，见 tune2 画质之后）—— 两个缺陷分开处置

**这是一次判据修改，按本文件开头的规矩留痕并说明理由。**

### 改了什么
原 §4 的「活」由 p_del + 指标画质红线判定，实测三条全过（p_del 65.0%、
配对方向为正、CLIPScore 相对 CountGen 反而 +0.12）。但逐张看图后
**画质实际不合格**，所以指标版红线作废，改为**肉眼红线**（见下）。
我在看图中途口头写过一条「出现嵌合体或拼接缝即判死方向 c」，那条规则
建立在「剩下唯一假设是遮罩几何」这个前提上，该前提已被证伪，故作废。
作废的理由不是结果不好看，是它的射程不覆盖新证据；替代规则写在下面，
且比原规则更严（多一道零容忍的目视门）。

### 为什么：证据表明是两个独立缺陷，不是一个
- **D1 遮罩几何**：待删框被保留框挖掉，中位 53%、最大 100%（表六）。
  发作于框重叠（密集）场景 → 嵌合体（半个杯子长成狗）或完全空转。
  `clock_num=7_seed=752770` 是极端例：待删框 100% 被挖，只重画了 24px
  膨胀环，YOLO 计数却从 13 掉到 10 —— **一个物体都没删，分数却涨了**。
- **D2 重去噪条件**：**遮罩正确时照样发作**。表七 ≤10% 层（遮罩兑现意图）
  的 `cell phone_num=5_seed=945501`，四个配置分别在洞里长出菜苗 / 煎蛋 /
  蓝笔 / 蓝笔。病根：base SDXL 的 4 通道 UNet 没被训练过 inpainting，
  RePaint 混合下它看不到"周围是什么"，遮罩区的去噪几乎全由**文本 + CFG**
  驱动。喂 `"A photo of the grass"` / `"background"` 配 guidance=5.0，
  等于请文生图模型画一张照片，它就画个主体出来。
  → **只换分割掩码不解决 D2。**

### 新的处置顺序与门槛（见数前登记）
先修 D2，因为它零下载、零新权重、一次 3 分钟，且它不过就没必要修 D1。

- **D2 的修法**（唯一允许的一组，不扫）：把遮罩区的条件降到最低 ——
  `prompt=""`、`guidance_scale=1.0`（等于关掉 CFG）、`negative_prompt` 保留
  类名。其余全部沿用 §3 的定死值。记为 prompt-mode `none`。
  理由：删除任务要的是**背景延续**，不是照本文生图；最小条件让模型只能
  依赖 latent 混合带来的邻域信息。
- **D2 的门（肉眼红线，零容忍）**：在表七 ≤10% 层那 **8 题**（遮罩已正确）
  上逐张看图，**8 题全部不得出现外来物体**（新长出的、与场景无关的主体）。
  出现 ≥1 例 → base SDXL + RePaint 做不了背景延续，机制不成立，
  **方向 c 终结，转诊断/评测协议论文**（这次没有下一张复活牌）。
- **D2 过了才修 D1**：把框遮罩换成 `yolov8x-seg` 的实例分割掩码
  （同一检测器家族的分割版，一个权重文件，仍零训练）。换模型后
  §2 的条件换算率 85.7% 不再直接适用，须在评测集 vanilla 上重量一次。
  然后 tune2 四格标定重跑，回到 §4 判生死。
- **本轮全部数字作废**：55.0% / p_del 65% / +10 / p=0.006 一律不得引用。
  表七显示 +10 里只有 6 分来自遮罩兑现意图的那层，另 4 分来自嵌合体带
  与空转带 —— 后者是**对检测器的规避**，不是计数修正。

## 6. 已知风险（现在写下，免得事后装惊讶）

- t_edit 未知：85.7% 在天生干净的 vanilla 上量得，编辑图只会更低。
- 洞里复生：重去噪可能重新长出目标类（negative_prompt=类名是唯一防线）。
- 密集粘连场景框重叠：删一个框的 mask 可能吃掉邻近实例的一部分。
- v8x 与 v9e 对"删干净了没有"的分歧直接吃掉收益（换算率的编辑图版本）。
- N>9 档按基准惯例不计分；tune2 已剔除。
