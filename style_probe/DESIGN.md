# 一、公式逐条对照（两篇全文读过）

## DICE（arXiv 2602.08059，训练无关，任务是**擦除**）

**对比三元组来自 prompt，不是来自真实参考图：**

| | prompt |
|---|---|
| Anchor `P_A` | 目标风格 + 内容 A（"A flower in the style of Van Gogh"） |
| Positive `P_P` | 目标风格 + **内容 B**（"A road in the style of Van Gogh"） |
| Negative `P_N` | **别的风格** + 内容 A（"A flower in the style of Monet"） |

**广义特征值问题（Eq. 13）：**

```
(Σ_AP' Σ_P'A) u  =  ρ (Σ_AA + λ Σ_AN' Σ_N'A) u        λ = 1.0
```

* 分子 `Σ_AP'Σ_P'A`：anchor↔positive 的交叉协方差 = **同风格、不同内容之间共享的东西** = style
* 分母惩罚项 `Σ_AN'Σ_N'A`：anchor↔negative = **同内容、不同风格之间共享的东西** = content

**位置**：style 子空间取 `down_blocks[0]`，content 子空间取 `up_blocks[3]`；时间步 0–400。
**用法**：`K' = K − γ·proj_{U_style}(K)`（正交抑制，Eq.17–18）、
`Q' = Q + γ_q (Q U_c) U_cᵀ`（内容增强，Eq.22）；γ 逐 token 由 sigmoid 调制。
**backbone**：SD v1.4。**开销**：3 秒。

## StyleGallery（CVPR 2026，训练无关，任务是**迁移**）

* **区域怎么来**：**DFCC** —— DDIM inversion 取 UNet 特征 → 时间加权融合 → **PCA** → K-means → 簇优化
* **风格区↔内容区匹配**：`Similarity = Σᵢ λᵢ·CS(featᵢᶜ, featᵢˢ)`，
  `λ₁=0.25`（统计）、`λ₂=1.0`（**语义，DINOv2 主导**）、`λ₃=0.125`（几何，弱语义时兜底）
* **注入**：Regional Style Loss（掩码后 self-attn 对的 L1）+ Global Content Loss（`‖Q−Q_c‖₁`）
* **位置**：**最后 6 个 UNet self-attention 层**，**150 步优化**
* **backbone**：SD 1.5
* **主表**：ArtFID **24.536** / FID 16.889 / LPIPS 0.3716 / Gram 13.519（StyleID 为 28.973 / 18.987 / 0.4496 / 14.261）

# 二、对照结果：三条订正，一条是好消息

## 订正 ①：提议的数学入口 = DICE 的 Eq.13，**逐项同构**

| 提议 | DICE |
|---|---|
| `max vᵀS_w v / vᵀS_b v` | `(Σ_AP'Σ_P'A)u = ρ(Σ_AA + λΣ_AN'Σ_N'A)u` |
| 「不同内容下仍然存在的方向」 | 分子：同风格不同内容的交叉协方差 |
| 「擅长区分语义区域的方向」（要压掉） | 分母：同内容不同风格的交叉协方差 |

**「style = 换了内容还在的东西；content = 换了风格还在的东西」这个逻辑，DICE 已经写成公式发表了。**
提议里那句「这是我认为最值得验证的数学入口」——**入口已经被走过。**

## 订正 ②：「对参考图做特征分解 + 区域聚类」也已经被做了

StyleGallery 的 DFCC 就是：UNet 特征 → **PCA** → K-means → 区域。
提议的第一步（拿到 `F_1…F_K`）**不是新的**，是 StyleGallery 的现成模块。

## 订正 ③（好消息）：**缺口比我上一轮说的更清楚，而且是两个弱点的交集**

| | DICE | StyleGallery | 缺口 |
|---|---|---|---|
| 参考风格必须**能命名** | ✅ 必须（要写 prompt 生成三元组） | ❌ 不必 | |
| 需要**几张图** | 3 张**生成**图 | 1 张真实图 | |
| 需要**测试期优化** | ❌ 否（3 秒） | ✅ **150 步** | |
| 任务 | 擦除 | 迁移 | |

* **DICE 做不了任意参考图**：它的对比源是「用 prompt 生成同风格不同内容」。
  给一张来路不明的画，你写不出那个 prompt。
* **StyleGallery 做得了任意参考图，但要 150 步优化。**

⇒ **两者的交集为空的那一格是：任意单张参考图 + 无优化 + 子空间投影。**

这比提议原本的 story（「我们挑战 F_s≈style 这个假设」）窄得多 —— 那个假设
StyleSSP（抑制）、StyleGallery（对齐）、DICE（分解）都已经在挑战了。
**但这一格是具体的、可 defend 的，而且两个弱点都是审稿人听得懂的。**

## 顺带：一个必须做的强 baseline

「把 DICE 的三元组换成用 IP-Adapter / SDEdit 从参考图生成的同风格不同内容图」
—— 这是 reviewer 一定会问的「你为什么不直接改造 DICE」。
**必须实现成对照臂，不能回避。**

# 三、诊断实验：`style_probe/subspace_look.py`

## 它只测一件事

> **单图内跨区域对比，分出来的到底是不是 style？**

因为这是唯一还没被占的那一条（对比源）。其余（公式、区域聚类、注入）都是现成件。

**不算指标、不做 ArtFID、不做标准表。产出是一张三列对照图，用眼睛看。**

## 三个臂（同 content、同 seed）

| 臂 | 注入什么 | 预期（假设成立时） |
|---|---|---|
| `full` | 参考图全部 K/V（≈ StyleID） | 有风格 **+ 参考内容泄漏** |
| **`proj`** | **只注入到 content-invariant 子空间上的投影** | **有风格，无泄漏** ← 想要的 |
| **`comp`** | **只注入正交补（"content-sensitive" 那半）** | **有参考的物体，无风格** |

**`comp` 这一臂是关键的证伪器。** 如果 `comp` 也带着笔触，说明根本没分开；
只有 `full` 和 `proj` 两列，看不出这一点。
（这条是 §11.12 negbranch 的教训：只有 base 一个参照不够，必须有反面对照。）

## 参考图怎么选 —— 这是本实验的核心，不能随便选

**必须选笔触逐区域差异明显的画**（天空平涂 + 树木厚涂那种）。

理由：我对这个假设的主要技术反对是——
> 「style = 跨区域共享」会把**随区域变化的渲染方式**当成 content 丢掉，
> 而那正是风格的重要成分。

一幅笔触全图均匀的画**测不出这个反对**。所以样本必须故意挑难的。
建议 6–8 幅，从 WikiArt 里手挑，并在文件里写明每幅"为什么选它"
（同 `fewstep_probe/look.py` 的 prompt 表）。

## 判读

| 看到 | 结论 |
|---|---|
| `proj` 保住逐区域笔触、`comp` 只剩物体 | **假设成立**，唯一的新颖点站得住 → 进方法 |
| `proj` 变得均匀平滑（厚涂那部分没了） | **技术反对成立**：区域对比会丢掉区域相关的笔触 → **判死** |
| `comp` 也带笔触 | 子空间没分开 → **判死** |
| 三列看不出差别 | 投影强度不够或位置不对 → 先查算子是否真生效（**调用计数器**，negbranch 的教训） |

## 实现要点（都是已有手艺的搬运）

1. **区域**：DDIM inversion 取 UNet 特征 → PCA → K-means（照 StyleGallery 的 DFCC，
   不需要分割模型）。K=4~6。
2. **散度矩阵**：在 self-attention 的 K/V 上按区域算 `S_b`、`S_w`。
3. **子空间**：解 `S_w u = ρ S_b u` 的广义特征问题，取前 r 个方向（r 扫 8/16/32）。
4. **注入**：写一个 self-attn processor，把参考 K/V 换成 `P_U(K_s)` 或 `(I−P_U)(K_s)`。
   —— `negbranch.py` 的 processor 直接改，**遍历 named_modules 设 `.processor`，
   0 条硬退出，带调用计数器**（那两条坑已经踩过）。
5. **位置**：先照 StyleID/StyleGallery 的惯例用**靠后的 self-attn 层**；
   DICE 用 `down_blocks[0]`（style）/`up_blocks[3]`（content）—— 两种都试，记下来。

## 必须先过的自测（否则读数无意义）

* **算子真被调用**（`calls > 0`、`proj_calls > 0`）—— negbranch 第一次就死在这
* **`P_U + (I−P_U)` 重构 ≈ 原 K/V**（数值断言，证明投影没算错）
* **r = 满秩时 `proj` 应当逐像素等于 `full`**（退化一致性）

## 成本

6–8 张参考 × 1 张 content × 3 臂 ≈ 20–24 张图，512²/1024²。**半小时以内。**

# 五、诊断结果：单图跨区域对比 **判死**（2026-08-16）

`subspace_look.py`，SD1.5 @ 512²，8 风格 × 3 content × 3 臂。

## 图上看到的（三个 content 完全一致）

| 列 | 现象 |
|---|---|
| `full` | **八种风格都清楚迁移**：水墨灰调、梵高蓝黄漩涡、浮世绘靛蓝、赛璐璐红桥白云、铅笔石墨、蒙娜丽莎暖褐、几何青绿块面、线稿纯线条 |
| **`proj`** | **八行几乎完全相同** —— 一片均匀的灰/米/绿雾，**看不出用的是哪张参考图** |
| `comp` | **几乎等于 `full`** |

## 判死的两条读数，第二条是决定性的

**① `comp` ≈ `full`** → 去掉那 16 维几乎什么都没变；剩下 304 维携带全部风格。

**② `proj` 跨行相同** → 如果那 16 维真是「内容无关的风格子空间」，
**不同参考图必须给出不同的 `proj`**。它们没有。
**那 16 维根本不携带风格信息，是与参考图无关的方向。**

## 根因：广义特征问题在这里是退化的（先从日志数字抓到，再数值证实）

日志里 `ρ_max ≈ 10⁵` 是红旗。核实：

```
d=320（up_blocks.3 通道数），k=5 → rank(S_b) = 4，零空间 316 维
找到的子空间落在 S_b 零空间的比例 = 1.0000
纯随机特征也能给出 ρ ≈ 1.6×10⁴      ← 与实测同量级
```

`S_b` 由 k 个区域均值构成 → **秩上限 k−1**。320 维里 316 维的分母 ≈ ε=1e-4，
广义特征问题几乎完全在零空间里挑方向，**ρ 的大小由 ε 决定，不携带任何
「这个方向是风格」的信息**。实际算出来的是「K/V 的 top-16 PCA」，
不是「风格 vs 内容」。

## 这条死因是**结构性**的，不是超参

> **单图内的区域对比，"内容"子空间的秩上限就是 k−1。**

k=64 也只有 63/320。而 `comp` 已经证明**从 320 维去掉 16 维就已经不产生
可见变化**，去掉 4 维（或 63 维）更不会有。
即使按正确方式实现（去掉 `S_b` 的 top-(k−1) 而非投影到 `S_w` 的 top-16），
**内容去除也弱到不产生效果**。

**⇒ 订正 §二 的结论**：我当时说「缺口是把 DICE 的多图要求去掉」。
现在看：**多图要求不是可以去掉的累赘，而是这个机制能work的前提。**
DICE 用跨图协方差，"content"方向的秩不受区域数限制 —— 那不是实现选择，是必要条件。

## 我事先那条技术反对 **没有应验**，此处订正自己

我反复强调"跨区域共享会丢掉**区域相关的笔触**，所以 hard 组会败、easy 组会成"。
**实测 easy 组（geo_pattern / line_ballerina）与 hard 组败得一模一样。**
失败与笔触是否逐区域变化**无关**。

杀死它的不是我事先想到的那条，是从日志 `ρ≈10⁵` 挖出来的秩退化。
**这是本 session 第四次「推导出来的东西被一次实测推翻」**
（离散-vs-连续表、置换保多重集、fp16 非确定性、区域笔触反对）。

## 两件留下来的真东西

1. **一个跑通的 SD1.5@512 StyleID 式 K/V 注入 harness**（`full` 那列为证），
   八种风格干净迁移。不管下一步做什么风格方向都能用。
2. **三臂设计第一次真正起作用**：没有 `comp`，我们会看到 `proj` 很糟，
   然后去调 r / 调注入强度 / 调层，浪费几天；有了 `comp` ≈ `full`，
   一眼就知道分裂方向从根上错了。**反面对照臂是这次唯一让结论可归因的东西。**

## 6.2 失效矩阵：结构存在，且**过了零假设对照**

# 七、2026-08-17 晚：命名尝试失败 + 一个必须先解决的归属问题

## 7.1 复现性：结构是真的（seed 0 / seed 2 两次独立抽样）

| | seed 0 | seed 2 |
|---|---|---|
| ΔS 画风效应 | 60.6% | 53.8% |
| ΔS 残差 | 26.7% | 33.1% |
| 负增益格数 | 46/800 | 44/800 |
| 内容效应（归一后） | 64.7% | 54.7% |

行效应稳定、负增益比例稳定、且都通过零假设对照。**「失效有结构」成立。**

## 7.2 命名尝试：**按事先判据失败**

假设是「低频 / 平涂类风格迁移不动」。判据事先写死：|r| ≥ 0.6 命名，
0.4–0.6 不够硬，< 0.4 否定。

| | 最强指标 | r |
|---|---|---|
| seed 0 @512² | flat | −0.484 |
| seed 2 @512² | flat | −0.427 |
| seed 2 @64²（判据尺度） | hf | +0.507 |

两个 seed 选出的最强指标不一致（flat vs hf、不同尺度），都没到 0.6。
**不再换指标继续找** —— 4 指标 × 3 尺度 × 3 seed 里挑一个过线的是 p-hacking。

中途的一个真收获：512² 上 row 19（橙子静物）是明确反例，grad/hf 全表最高
却在最差组 —— 因为那张画有**画布织纹**，像素尺度的高频被织纹主导，而织纹
不是画风。正确尺度由架构给定（注入层的 latent 分辨率），不由人挑。

## 7.3 ★ 必须先解决的归属问题

查 `subspace_look.py`：我们的 harness **没有** init AdaIN、**没有** query
preservation (γ)、**没有** attention temperature (T)，只有裸 K/V 交换 +
前向加噪 + img2img strength，30 步，up_blocks 9 层。

StyleID 的四个组件我们只实现了一个。**所以今天的 2400 张不是 StyleID，
是「去掉三个组件的 K/V 注入」。** 上一版 DESIGN 里我把 row 19/36 的破坏
归因于「初始 latent 的 AdaIN 把调色板糊开」—— 那是错的，我们的运行里
根本没有 AdaIN。此处订正。

继续在这上面找 problem statement，找到的很可能是我们自己简化出来的性质。
这与「256px style 池」「GroundingDINO 指标」是同一类错误。

# 八、2026-08-18：**评测链验证通过** + StyleID 的因果分解

## 8.1 ★ 锚点对上了

在 StyleID 自带的 40 style × 20 content 上、按论文配置（SD1.4 / DDIM 50 步 /
γ=0.75 / τ=1.5 / 注入层 7-11 / 512² center-crop）跑作者自己的 diffusers 实现：

| | 我们【一手实测】 | 论文 Table【一手】 | 差 |
|---|---|---|---|
| ArtFID | **29.190** | 28.801 | **+0.389** |
| FID | 18.409 | 18.131 | +0.278 |
| LPIPS | **0.5039** | 0.5055 | **−0.0016** |

事先写死的判据是 |ΔArtFID| < 1.0 通过。**通过。** 这是 diffusers 实现对
ldm 实现，差 0.39 属于实现差异的合理范围。

**意义：数据、生成、评测三层都验证过了，从此我们的数在那张表上。**

## 8.2 两个部件的消融（用在位者自己的开关）

| 配置 | ArtFID | FID(风格) | LPIPS(内容) | ΔS 均值 | 负增益格 |
|---|---|---|---|---|---|
| full | 29.190 | 18.409 | 0.5039 | 0.1049 | 6/800 |
| no_adain | **29.358** | 20.489 | **0.3662** | 0.0834 | 21/800 |
| no_inject | 41.510 | 25.630 | 0.5587 | **0.0044** | **378/800** |

### ① 风格几乎全部来自 K/V 注入

关掉注入后 ΔS 均值 **0.1049 → 0.0044**，378/800 格变负增益。

**这否掉了 §六 的假设**：我猜「平涂类风格的迁移靠 AdaIN 硬涂调色板」，
实测 AdaIN 单独提供的风格靠近约等于零。此处订正。

### ② init AdaIN 在 ArtFID 上几乎不做事

29.190 → 29.358，**差 0.17，比我们自己的复现误差 0.39 还小**。
但拆开看：FID +2.08（风格变差）、LPIPS −0.138（内容变好）。

即：**AdaIN 只是沿「风格↔内容」权衡曲线挪了一格，乘积上是白做的。**

与论文自己的消融一致：A(γ=0.75) 28.80 → A*(γ=0.6) **27.97**，
**光调 γ 就有 −0.83**，比整个 AdaIN 组件贡献的还多。两个旋钮做同一件事，
而 AdaIN 停在一个不划算的点上。

### ③ 由此得到的贡献判据（可证伪）

**ArtFID 沿权衡曲线方向是平的。** 任何只调 γ / 只改颜色对齐的改动都换不来分；
要赢 StyleID，必须**垂直于**那条曲线走——不牺牲内容而拿到风格，或反之。

这同时解释了为什么这条线上的后续工作大多只能挪零点几。

## 8.3 还没做的：逐 style 的分解

总体的 0.17 是均匀摊在 40 个 style 上，还是集中在少数几个？
若集中，那几个就是可命名的对象。`decomp.py` 回答这个。

判据（事先写死）：
* **AdaIN 的风格收益 vs 内容代价，逐 style 求 r**。r 接近 +1 → 每个 style 都在
  同一条权衡曲线上，没有可乘之机，这条线到此为止；
* **r 明显小于 1** → 存在「代价小收益大」的 style，那才是能改的地方。
