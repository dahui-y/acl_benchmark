# 第一步结果：校验器标定（415 格 / 47 类 / N=1..5 / COCO val2017）

日期 2026-08-05。判据写在 `README.md`，**在看到任何数字之前**。

> **判决：按预先注册的判据 —— 🔴 不过。两个检测器都不过。**
> 把测量重新指定为"复数 vs 单数"之后 —— 🟡 有条件过（0.880 / κ 0.681）。
> **这是"换了个量之后有条件过"，比"过"弱一档，不能当成过。**

---

## 1. 预先注册的那个量：恰好几个

| 检测器 | 精确计数 | κ | 加权 κ | N-vs-1 有序率 |
|---|---|---|---|---|
| `mask2former-swin-large-coco-instance`（GenEval 用的那个） | **0.605** [0.559, 0.653] | 0.513 | 0.672 | **0.846** [0.761, 0.916] |
| `owlv2-base-patch16-ensemble` | **0.472** | 0.375 | 0.209 | **0.812** |

判据：🟢 = 有序率≥0.95 **且** κ≥0.70；🔴 = 有序率<0.85 **或** 加权κ<0.60。

**没有任何一个阈值让任何一个检测器进入黄区。** mask2former 在精确计数最优点（0.70）
上有序率 0.808，在有序率最优点（0.10）上加权 κ 只有 0.290——两条红线各触一次。
owlv2 更差，且在低阈值下暴涨（0.10 时平均多数 **+4.19** 个）。

**"恰好几个"这个问题，检测器答不了。** 这是本步最硬的结论。

分离度的 bootstrap 区间 [0.761, 0.916] 宽到跨过 0.85——415 个格子**分辨不了自己的判据线**。
这是我标定设计的缺陷，得记着：下次设阈值要先算需要多少样本。

---

## 2. 重新指定的量：复数 vs 单数（**非预先注册**）

给检测器出"恰好几个"是我出错题了。基准真正的对立——
"三个女孩**各自**拿一个气球" vs "**一起**拿一个气球"——**本来就是复数对单数**。

| 检测器 | 平衡阈值 | 复数判定 | κ | FP(1→多) | FN(多→1) |
|---|---|---|---|---|---|
| **mask2former** | 0.575 | **0.880** | **0.681** | 0.122 | 0.120 |
| owlv2 | 0.250 | 0.817 | 0.532 | 0.211 | 0.175 |

mask2former 峰值 0.908 / κ 0.719（thr 0.10），但那个点 FP=0.267、FN=0.043，
**误差全压在集体条件上**。阈值按误差平衡选而不是按峰值选：
把 1 个误判成"多个"污染集体条件，漏检污染分配条件，
只追准确率会让偏差正好落在这个基准要做的那个比较上。

分档（mask2former, thr 0.60）：N=1 **0.889** · N=2 0.789 · N=3 0.867 · N=4 0.944 · N=5 0.945。
**N=2 最弱，设计上应丢掉，主用 N∈{3,4,5}。**

**代价，写在明处：**
- "恰好 3 个"的分辨力没了。模型给"三个女孩各拿一个"画**两个**气球也算过。**削弱构念。**
- 难度轴从"数对没有"降级成"有没有复数化"；精确计数只能作带误差棒的次级指标。
- 仪器自身 12% 误差，直接进主结果的误差预算。

---

## 3. 两器交叉——顶替人工核验那一格，代价是覆盖率

| | |
|---|---|
| 两器一致率 | 0.807，κ 0.538 |
| 一致子集 | 335/415 = **80.7% 覆盖** |
| **一致时的正确率** | **0.931** [0.901, 0.958] |
| 丢掉的 80 格分布 | N=1:14 · N=2:21 · N=3:14 · N=4:18 · N=5:13 |

好消息：丢掉的格子**在各档上是均匀的**，没有系统性吃掉某一个条件。
坏消息：0.931 是**只报一致子集**换来的，19% 的格子被丢掉，
论文里报 0.931 就必须同时报 80.7% 的覆盖率，否则是选择性报告。

而且 owlv2 明显更差这件事本身削弱了这条路：
**"两个独立检测器互证"的说服力取决于两个都可信**，现在其中一个 κ 只有 0.532。

---

## 4. 这一步真正教给我们的

1. **"恰好 N 个"不可测，"多于一个"可测。** 构念要按仪器能回答的问题重写，
   而这次重写恰好更忠实于语义对立——不是迁就。
2. **N=2 不能用。** 余量太小。
3. **标定集要更大。** 415 格分辨不了 0.85 这条线。
4. **仪器不止 mask2former 和 owlv2。** 这一步只否定了这两个，
   没有否定"用程序真值"这条路本身——见下。

---

## 5. 下一步（顺序有变）

**原计划是第二步别名封口、第三步 pilot。现在应该先插一步：换仪器再测一轮。**

理由：**仪器是这条路唯一的约束点**，而我们只试了两个，
其中一个还是我选错的类型（开放词表检测器在"数同类物体"上没有优势，已实测）。
标定架子已经搭好，加一个检验器只是 `detect.py` 里多一个类，同一批 415 格重跑一遍。

值得试的三个，按预期收益排：

| 候选 | 为什么 | 成本 |
|---|---|---|
| **MLLM 计数器**（GPT-5.2 / Qwen2.5-VL 问"图里有几个 X"） | T2V 那条线的判官代码可以直接改用；**关键是这里有 COCO 金标注可以标定它**，而 T2V 那边没有——这正是两条路的分水岭 | Mac 上跑，415 次调用 |
| **GroundingDINO** | 另一种开放词表架构，与 owlv2 的失败模式未必相同 | 4090 上 ~15 分钟 |
| **CountGD / GeCo 一类计数专用模型** | 专门为"数同类小物体"训练的，正是我们的场景 | 需查是否有可用权重 |

**如果 MLLM 计数器在同一批格子上能到 0.95 / κ≥0.8，整条路的地基就换成它，
"恰好 N 个"的主结果可能救得回来。** 如果它也在 0.88 附近，
那就接受"复数 vs 单数"这个降级版本，带着 12% 的仪器误差往下走。

之后再回到第二步（别名封口）和第三步（pilot 400 张）。

## 复现

```bash
python cells.py --max-count 5 --per-n 90 --per-class-n 10
python detect.py --detector mask2former
python detect.py --detector owlv2
python report.py --pred data/pred_mask2former.jsonl data/pred_owlv2.jsonl --screen
```

CPU 上 mask2former ~1.5 s/图、owlv2 ~3.3 s/图，全程约 35 分钟，不需要 GPU。
