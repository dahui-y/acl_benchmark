## 1. 立项依据（全部一手，evaluation set 全量 167 题）

### 1.1 复现基线（cocoount2，与最早那批逐项一致，全集数值透明已验证）
CountGen **56.9%** / vanilla **40.1%**；MAE 1.000 / 1.485；
DBSCAN 与 YOLOv9e 一致率 64.1%、MAE 0.89。
（`N>9` 的 33 题被官方 `run_countgen.py:104` 整题跳过，不计分，报数须写明。）

### 1.2 损失全部发生在「布局 → 图像」这一步
经过布局引导的题共 **98** 题（其余 69 题 `obj_num_match=True`，原样返回
vanilla，按定义无引导可分析；54+41=95，95/167=56.9% 对账成立）。
其中 ReLayout 把 blob 数改对的有 **97/98**，而最终数对的只有 **41.8%**。

> **给定一个恰好含 N 个分离区域的布局，CountGen 的引导生成只有 42% 的
> 概率产出恰好 N 个物体。**

### 1.3 误差的精确摊派（`blob_split.py`，恒等式 yolo − k = 多长 − 空blob + 背景漏）

| 归属规则 | 多长下界 | 空blob下界 | 背景漏 | 判据比值 | 错题里有下界多长 |
|---|---|---|---|---|---|
| cover 0.00 | 80 | 54 | 1 | 59.3% | 36/57 (63%) |
| cover 0.15 | 86 | 67 | 8 | 53.4% | 34/57 (60%) |
| cover 0.30 | 73 | 116 | 70 | 28.2% | 29/57 (51%) |
| centroid（最保守） | **40** | **65** | **52** | **25.5%** | **25/57 (44%)** |

- 「多长下界」= 即使按最有利于「没有重复生成」的方式分配每一个框
  （框-blob 二分图最大匹配），仍然消不掉的「一个 blob 里不止一个物体」。
- **背景漏 ≈ 0**（cover 0.00 下 465 个 blob、约 500 个框里只有 1 个）。
  → **自注意力遮罩在它自己那份职责上是做满的，那里没有空间。**
  （自我否定：先前设想的「把遮罩扩到更多步/更多分辨率以防背景冒物体」作废。）
- 类别混杂已排除（见 1.4）。

### 1.4 「检测器类别伪影」假说被否定
`多长下界` 分布在 **13–17 个类**上，四条归属规则下**前两类占比 33.7–37.5%**，
一致地低于预登记的 50% 门槛。最苛刻处理——删掉头名 tie 用最保守的 centroid
规则，比值仍有 **21%**；再删掉第二名 clock，仍有 **17.6%**，高于 15% 的作废线。

### 1.5 论文自己承认、且未解决

### 1.6 代码级的表达力缺口（两处，互相印证）
- `utils/loss_utils.py:5`　`foreground_mask = (desired_mask != 0)`
  → 布局的**实例编号被二值化丢弃**。
- `pipeline/attention_processors.py:45-61`　`blob_coordinates` 是**所有 blob

  论文 §3.3 公式同：`S*[i,j]=0 if i∈B(l) and j∈F(l)`，F 是前景**整体**。

> **CountGen 从自注意力里「读」出了实例身份（`l^up_52` + DBSCAN，这是它的

### 1.7 判据状态的诚实记录

## 2. 方法（两个机制，各治一个通道；均训练自由、零新权重、零 LLM）

误差有两个方向相反的通道，需要两个不同的机制：

| 通道 | 物理含义 | 对症机制 |
|---|---|---|
| 多长（下界 40–86） | 一个 blob 内**裂出**多个物体 | **B 软亲和损失**（blob 内现象，切跨 blob 注意力治不了） |
| 空blob（下界 65–116） | 位置没长出来，含两 blob **合并**成一个 | **A 硬跨 blob 遮罩**（部分） |
| 背景漏（≈0） | 长到布局之外 | 已解决，不动 |

### A. 跨 blob 自注意力硬遮罩（零梯度、零显存增量）
现有：`S*[i,j] = 0  if i∈B, j∈F`（F = 所有 blob 的并集）。
新增：`S*[i,j] = 0  if i∈blob_a, j∈blob_b, a≠b`。
即每个实例只能从**自身区域 + 背景**聚合特征，不能与邻居互相拷贝。
作用层与步区间沿用原版（`up` 块 32×32、步 0–10），**不扫**。

⚠️ 实现注记：原版置零后**不重新归一化**（注意力行不再和为 1，背景 token
输出被衰减）。这可能是无心之失。A 沿用原样**不归一化**，以保持与基线可比；
「是否归一化」列为消融项而非标定项（见 §4）。

### B. 实例级自注意力亲和损失（新损失，作用在 `l^up_52`）
论文用 `l^up_52` 在 `t=25` 的自注意力做 DBSCAN 聚类**读出**实例
（`dbscan_mask_extract.py:181`，`layers=['up_52']`）。B 把同一张亲和矩阵
拿来**写入**：

    L_aff = mean_{i,j 同 blob} (1 − A[i,j]_norm) + mean_{i,j 异 blob} A[i,j]_norm

其中 A 是 `up_52` 的自注意力概率（存储时已对头平均，形状 (1,1024,1024)），
`_norm` 用与原版 `object_layout_loss` 相同的 min-max 归一化，以免重蹈
方向 a 查明的量纲失配（FINDINGS §2.3）。
直觉：**这是「让 DBSCAN 恰好读出 k 个簇」的可微版本**——一个 blob 裂成两个
物体，其内部亲和矩阵会出现两个子块，第一项直接罚它。

总损失：`L = L_cross + λ · L_aff`，`L_cross` 与步区间（0–25）沿用原版不动。

**λ 的定法（规则而非扫描）**：在 5 道**不参与任何评测的**预热题上，取 λ 使
`λ·L_aff` 在步 0 的初值等于 `L_cross` 在步 0 的初值（量级对齐），四舍五入到
一位有效数字后**定死**。不扫 λ。

### 三个配置（这就是全部标定预算）
    A      只加硬跨 blob 遮罩
    B      只加软亲和损失
    A+B    两者同时

## 3. Gate 0 —— 工程前提（先做，不过则降级并留痕）

显存估算：`up_52` 自注意力在计数前向里是 `(20 heads, 1024, 1024)` fp16
≈ 42 MB，存储时对头平均后为 `(1,1024,1024)` ≈ 2 MB。原版
`update_latent` 用 `create_graph=True`（二阶图），叠加后是主要风险来源。

**通过条件（5 题冒烟）**：
1. 不 OOM，单题耗时相对原版增加 ≤ 50%；
2. **断言 `L_aff` 对 latent 的梯度非零**——否则等于没接上，会静默变成
   「只跑了原版」。这条必须写成 assert，不能靠看曲线。

不过 → **只做 A**，B 与 A+B 取消，方法完整性打折这一点必须写进论文，
不得假装原本就只打算做 A。

## 5. 生死判据（tune3 上，四道门全过才进评测集）

前两个方向都死于同一个形状：**机制点火了，指标不动**（方向 a：损失降 91%、
准确率一动不动；评测集 p=1.000）。所以本次的门必须包含**机制与分数之间的
逐题因果链**——那正是前两次缺的一环。

- **Gate 1（机制真的动了）**：最优配置在 tune3 引导题上的
  **多长下界（centroid 规则，最保守）** 相对同批 CountGen **下降 ≥25%**。
  不降 → 机制没做到它声称的事 → **死**。
- **Gate 2（机制与分数有逐题因果链）**：把引导题分成「多长下界下降」与
  「未下降」两组，比较各组「由错变对」的比例。要求
  **(a) 下降组比例 ≥ 2 × 未下降组，且 (b) 下降组至少 8 题**。
  同时报 Fisher 单侧 p 作为**信息**——tune3 的引导题约 53 道，功效低，
  **明说不以 p 作门槛**，此门必要而不充分，评测集仍是最终仲裁。
- **Gate 3（分数）**：tune3 整批相对同批 CountGen 的配对 McNemar
  **方向为正且净 ≥ +5 题**。
- **Gate 4（画质红线，肉眼，零容忍）**：按固定规则选 8 题（多长下界降幅
  最大的 8 题，规则先定、不许挑），逐张与同批 CountGen 并排看，
  **不得出现畸变、嵌合、明显不自然**；CLIPScore 相对同批 CountGen 均值
  不降超过 0.3。
  （方向 c 的教训：指标版红线全过而肉眼全崩。本次肉眼优先。）

**任何一门不过 → 方向 d 判死 → 转诊断/评测协议论文，不再有方向 e。**

## 6. 评测协议（防循环性，三重；沿用 DESIGN §5）

1. 主口径：YOLOv9e，与 CountGen 同一评测链、配对 McNemar。
2. 第三方：OWLv2 对两臂同测（绝对值噪，两臂差值有意义）。
3. 作者盲数：主对比子集上盲法人工计数，披露作者自评 + 盲法 + n + 检验方法。

⚠️ **本方向特有的循环性，必须在文中显式披露**：B 直接优化 `up_52` 的自注意力
亲和结构，而 DBSCAN 正是从同一张矩阵读出计数。**内部计数指标因此是自我实现
的，一律不得作为效果证据**；只认外部检测器与盲数。

## 7. 已知风险（现在写下，免得事后装惊讶）

- **自我实现的循环性**（见 §6）——这是本方向最容易被审稿人抓的一点。
- **过约束伤画质**：论文自己说 test-time optimization 会降自然度
  （§4 Image quality evaluation、§7 Limitations）。硬切断跨 blob 注意力
  可能破坏全局一致性（光照、风格、遮挡关系）。
- **「空blob」通道有一部分不是生成失败，是检测器漏检**（飞机题最典型：
  天上小飞机 YOLO 大量漏检）。本方法治不了漏检，Gate 1 只以「多长」为准，
  正是因为漏检**不能**凭空造出额外的框、无法虚高「多长」。
- **B 可能治不动「多长」**：blob 内裂开是否真的在 `up_52` 的亲和矩阵上表现为
  两个子块，是一个**假设**，Gate 1 就是用来证伪它的。
- 显存/二阶图（Gate 0）。
- N>9 档按基准惯例不计分。
