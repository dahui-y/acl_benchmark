# 选题调研索引与最终结论

基于对 `OSCBench`（ACL 2026 main）的分析，经五轮调研后的选题决策记录。

**筛选标准**：空白 + 与 OSCBench 同等稳健 + 达到 ACL main 标准 + 标注成本可承受（无标注团队）。

---

## 最终推荐（2026-08-03 修正后）

> ### 语法体与终结性在视频生成中的实现（`idea_aspect.md`）
>
> **研究问题**：语言中编码"事件是否达成终点"的语法手段（体貌、终结性、相位动词），
> 能否控制视频生成模型的输出？
>
> **动机**：T2V 正被用作世界模型、合成数据引擎与视频编辑底座，
> 这些用途均要求用户能指定**动作是否达成**——"要结果态、不要过程"
> 是视频编辑与训练数据合成的常规需求。若模型对这套语法手段失明，则该维度上不可控。
> VBench-2.0 已记录"啃食物但食物没变少"这类 fake motion 并归为常识失败；
> **真正没人问过的是：这件事能否被语言控制。**
>
> **遗留缺陷与修法**：唯一实质缺陷是"gold 由作者规定"。
> 修法为**别写 gold，去测 gold**——给标注者看真实视频，问哪个体貌形式的描述合适，
> 由人的判断反推目标映射；同时白赚一份"人类体貌—视频映射"资源。
> 弱化的不可反驳主张：不规定应生成什么，只主张
> `is slicing` 与 `has sliced` **不应产生相同的输出分布**。

### 为何不再推荐预设投射

后续核实 NEGATE 后发现两个问题，第二个是结构性的：

1. **生态效度接近于零** —— 真实用户不会写 `The man didn't stop slicing the apple`
2. **最可能的实验结果恰使研究失效** —— NEGATE 证明模型主要失败模式是
   "inclusion despite negation"（照样生成被否定内容），
   则模型会为 `didn't stop slicing` 生成切削动作，**看似投射成功，实则只是忽略否定**

方向 ④ 的缺陷可靠设计修复；方向 ⑤ 的缺陷不能。详见 `idea_presupposition.md` 顶部说明。

## 动机与贡献：与 OSCBench 的对照

**"空是否因为没价值"是必须先问的问题**——第五轮的预设方向正是栽在这一条上。

| | OSCBench | ④ 体貌 | ⑤ 预设 |
|---|---|---|---|
| **动机类型** | 下游应用（教学视频、机器人、具身智能） | 下游应用（可控生成、视频编辑、数据合成） | **纯科学问题** |
| **失败的实际后果** | 大 | 大 | **接近于零** |
| **研究问题** | 模型是否忠实实现语言指定的动作后果？ | 语言能否控制事件是否达成？ | 模型是否生成被预设的内容？ |
| **贡献形态** | 资源 + 协议 + 多模型 + 相关性分析 | 同构，**多出机制定位与免训练干预** | 同构，但结果可能不可解释 |
| **结果可解释性** | 高 | 高 | **低（偶然正确的混淆）** |

→ 方向 ④ 在动机与贡献上**与 OSCBench 持平甚至略强**（多一个机制层）；
方向 ⑤ 在动机上**明显弱于** OSCBench。

**既是预设触发语、也是体貌算子**，作为 ④ 的一行保留，但不承重。

以下设计要求由前几轮继承，适用于 ④：

| 要求 | 出处 |

## 第六轮修正（2026-08-03）

**方向 ④ 重定位为「语言控制的非达成」**，详见 `idea_aspect.md` 末尾第六轮章节。

- **坏消息**：`RoboTrustBench`（arXiv 2606.01600）已把 action completeness 列为评测维度
  → 新颖性收窄为"**达成与否能否被语言控制**"，须在 related work 写死区分
- **好消息**：找到硬价值故事——具身智能的**失败数据缺口**
  （立场论文 arXiv 2606.01036 明确呼吁），现有方案全靠扰动轨迹，**语言路径无人走**
- **顺带修好了遗留缺陷**：`tried to slice but failed` 的目标无歧义，
  不再需要"用真实视频反推 gold"的补丁
- **理论挂靠**：未完成体悖论（Dowty）——`was crossing` 不蕴含 `crossed`

## 方向 ④ 原待处理的两处（其一已由第六轮解决）

1. **gold 不能由作者规定**。`has sliced` 到底该生成什么样的 5 秒视频，
   是形式语义审稿人会直接打穿的地方。
   修法：给标注者看**真实视频**反推目标映射（顺带产出"人类体貌—视频映射"资源）；
   或退到不可反驳的差分主张——只主张 `is slicing` 与 `has sliced`
   **不应产生相同的输出分布**。
2. **轴过窄**。单一语法范畴撑不起 benchmark 体量。
   扩展为"语言对事件达成的编码"：体貌 + 终结性（光杆复数 vs 定指）
   + 相位动词（begin / stop / finish，由方向 ⑤ 并入）+ 程度成就动词；
   base 事件提到约 200。

## 探针已完成（2026-08-03）

在 umT5-XXL（Wan 2.1/2.2 实际编码器）上跑通，结果见 `probe/RESULTS.md`：

- **mean SNS = 0.79，4/5 体貌条件低于 1.0** —— 改变事件是否达成，
  比往句尾加四个无意义词移动得更少。t5-base 上为 0.91，两编码器一致。
- 判定 **INFORMATION PRESENT BUT LOW-MAGNITUDE** → 编码器瓶颈叙事排除，原方案成立
- **意外收获**：`paraphrase_min` 与 `other_verb` 编辑距离同为 0.103，
  二者差值（0.34 → 0.49）是纯语义标尺。`atelic` 仅 0.36 而编辑距离是其两倍
  —— 这个三方对比可作论文主图
- **坏消息**：逐层探针全程 ~1.000 平线，**「机制定位」一节不成立，须从规划中删除**；
  免训练差向量干预相应**从加分项升为必需**

## 下一步（两条路，都不贵）

- **验证路线**：先跑文本编码器探针，确认编码器是否区分
  `didn't stop slicing` 与 `stopped slicing`。纯文本、不需标注、两种结果都能写成一节。
- **构造路线**：按扩展后的体貌 / 终结性矩阵，配合本仓库 `action_object_taxonomy/`，
  生成 prompt 集；并用真实视频做小规模标注，经验地确定体貌—视频的目标映射。
