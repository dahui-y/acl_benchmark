# 首批真实视频的观察

对象：`wan2.2-ti2v-5b-480p`，item 0（`grating` + `carrot`，incremental_theme），
seed 42。两轮：先 `prog`/`perf` 两条 × 5 帧，后扩到 7 条 × 8 帧。

**一个 item、一个种子。样本量为 1。** 下面区分**画面上明确看得到的**
与**这个样本量下判断不了的**。任何"模型能/不能"的结论都要等全量数据。

---

## 明确看得到的

### 1. 共享种子按预期工作，而且是肉眼可见的

七行的首帧共享同一个箱式擦丝器、同一块砧板、同一角度、同一个厨房背景、
同一片前景橙色。**构图被种子钉死，变的只有砧板上的物体状态。**

这是这个设计能成立的全部前提：**场景不变，只有我们关心的那个变量在动。**
（唯一的例外是 `failed`，见下。）

这正是整个设计要的东西：两行之间任何差异都不可能来自"模型这次想画个别的厨房"。
`max |Δpixel| = 0.000000` 那条是数值证据，这张图是可以放进论文的视觉证据。

### 2. 480p 够用，这个问题可以结案

擦丝器的孔、胡萝卜的形状、案板上的碎屑、手指的位置，在 480p 下全部清晰可辨。
标注问的是"物体有没有到达目标末态"，这个分辨率答得了。
**降分辨率这处偏离，在构念层面不构成损失。**

### 3. 各行确实不同，不是同一段视频

条件之间明显分叉。**模型对体态改写不是完全无反应的。**
如果各行逐帧相同，这篇的主实验会非常难写——现在不是这个局面。

## 第二轮：第一轮那条观察要修正

第一轮只看了 `prog`/`perf`，我据此说"首帧里已经有擦好的丝，末态产物一开始就在画面里"。
**看到七行之后，这个描述不准确，而且方向反了。**

真实情况是：**画面最前景那一小片橙色是种子决定的常量，所有条件都有**；
而**砧板上的物体状态随条件而变**——而且变得相当合乎语义。这不是噪声，
这正是信号所在的地方。

原来那条关于"状态式提问不可用"的结论仍然成立，但理由变了：
不是因为产物一开始就在，而是因为**模型改的主要是首帧状态本身**（见下）。

## 最重要的一条：模型改的是「初始状态」，不是「过程」

七行按首帧砧板上的东西分组：

| 条件 | prompt | 首帧砧板上 |
|---|---|---|
| `prog` | is grating **a carrot** | 一根完整胡萝卜（带缨） |
| `perf` | grated **a carrot** | 一根完整胡萝卜（带缨） |
| `prospective` | is about to grate **a carrot** | 一根完整胡萝卜（带缨） |
| **`result`** | **has grated** a carrot | **一堆胡萝卜丝，没有完整胡萝卜** |
| `atelic` | is grating **carrots** | 一堆胡萝卜块/片 |
| `telic_plural` | is grating **the carrots** | 一堆胡萝卜块/条 |
| `failed` | tried to grate ... **but failed** | 一根变形的胡萝卜，构图整体失控 |

两条读得出来的规律：

**1. `result`（has grated）把场景直接渲染成了结果态。** 不是"演一遍过程最后得到丝"，
而是**开场就是丝，完整胡萝卜根本不出现**。从语义上说这其实是对的——
完成体断言的是参照时刻上结果状态成立。**模型对 have+PP 有反应，而且方向正确。**

**2. 单复数被渲染了，定指性没有。** `atelic`（carrots）与 `telic_plural`（the carrots）
都给出多块胡萝卜，彼此大体相似；而三个单数条件给一根。
也就是说**数被编码，有界/定指没有**——这正是终结性轴预期的分离模式。

这两条都是**预期方向**，而且是在同一张图里同时出现的。n=1，不能当证据，
但足以说明这个设计**测得动东西**，不是在测噪声。

## 由此改定的标注编码方式

不要用单一的"末态是否达成"。要**把首帧状态与末帧状态编成两个独立变量**，
再看两者之差：

| 条件 | 首帧预期 | 末帧预期 |
|---|---|---|
| `prospective` | 未受影响 | 未受影响或刚开始 |
| `prog` | 未受影响 | 部分完成 |
| `perf` / `result` | 结果态已成立 | 结果态 |
| `failed` | 未受影响 | 未达成 |

这套编码比二元判断信息量大得多，而且**直接对应语义预测**，
不是事后凑出来的指标。首帧编码同时充当筛查项。

## 一条警告：`failed` 那行构图崩了

`failed` 是唯一构图明显偏离共享种子的一行——机位变了、出现了别处没有的红色底座、
胡萝卜形状扭曲、中间还有一帧近乎糊掉。

两种解释，现在分不开：

1. **语义解释**：模型渲染不了"尝试但未遂"这种否定性事件，于是崩坏
2. **长度解释**：`failed` 的 prompt 明显最长，长度本身把条件向量推远了，
   连带把整个场景推走了

**这两个必须分开，否则 `failed` 这一格没法解释。** 分开的办法现成：
文本侧本来就有 `filler`（长度配平、语义不变）这个条件，
之前为省算力没放进视频侧。**现在应该放进去**——它正是用来回答
"是长度还是语义"的那个控制。代价约 6%（16 → 17 条，两模型 +0.5 天）。


## 这个样本量下仍然判断不了的

- **`perf` 与 `prog` 的区别。** 两行都从完整胡萝卜开始，末段都是短胡萝卜加碎屑。
  `result`（has grated）反应强烈，`perf`（grated，一般过去时）却没有——
  这可能是真的（简单过去不像完成体那样断言结果状态在参照时刻成立），
  也可能只是这一个种子的偶然。**这一格是全套设计里最值得看的一格。**
- **过程有没有被演出来。** 8 帧下仍看不到明确的"贴着擦面来回推"。
  各行更像是在演"擦丝这件事的场景"，而不是"擦丝这个过程"。要看完整 mp4。
- **方向是否稳定。** n=1。

## 下一步

1. 补双锚：`--conditions other_verb paraphrase_min`，约 7 分钟
2. 把 `filler` 加进视频条件（长度控制，用于解释 `failed`）
3. 换 2–3 个 item、换种子看同一批条件，确认上面两条规律不是这一格的偶然
4. 直接看完整 mp4，确认动作是否被执行
5. 标注协议按"首帧状态 + 末帧状态两个变量"起草

# 第三轮：双锚 + 长度控制 + 换 item

`item 0` 加了 `filler` / `other_verb` / `paraphrase_min`，另跑 `item 1`
（`mashing` + `plantain`，degree_achievement）的四个体态条件。

## 好消息：长度控制立刻见效，`failed` 的解释定了

`filler`（"…, as the footage shows."，语义不变、长度与 `failed` 相当）
**也偏离了共享种子的构图**：擦丝器换成了红色底座那一款，砧板上从完整胡萝卜
变成了切好的丁——而**红色底座正是 `failed` 那行才有的东西**。

两个最长的 prompt 出现了同一种偏离，而它们的语义毫无共同点。
**所以 `failed` 的构图崩坏是长度效应，不是"模型渲染不了否定事件"。**

这条结论正是加 `filler` 要买的东西，而且第一眼就买到了。同时它也说明：

> **共享种子只在 prompt 长度相近时才钉得住场景。**

这必须写进方法一节。`failed` 这一格只能相对 `filler` 解释，不能相对 `prog` 解释。

## 坏消息：下锚不在零点

`paraphrase_min`（`in the kitchen` → `inside the kitchen`，**改一个介词**）
**也把砧板从完整胡萝卜改成了切丁**，看上去和 `filler` 那行相当接近。

这是这批图里最重要的一条，而且它**削弱了我上一轮对 `result` 的兴奋**：

- 如果一个介词的同义替换就能改变宾语的初始状态，
- 那 `result`（has grated → 开场即丝）的差异**未必来自体态**，
  可能只是"token 序列被扰动了"的一般效应。

**下锚不在零点，就不能把任何条件差异直接当作体态效应。**

### 由此定下的分析方式

和文本侧的 SNS 统计量同构：**所有视频侧的条件效应都要除以 paraphrase 基线**。

```
体态效应 =  d(prog, result)  /  d(prog, paraphrase_min)
```

比值接近 1 就是没有体态特异的效应。这条不是事后补救——
文本侧探针当初就是因为松散的 paraphrase 抬高了噪声底而做过一次自我推翻，
同一个教训在视频侧原样重演了一遍。

**上锚是好的：** `other_verb`（mincing a carrot）画面里**连擦丝器都没有**——
切丁用刀不用擦丝器。模型确实在读动词。

## 又一类词表缺陷：歧义名词

`item 1` 四行**全军覆没**：画面里是一株阔叶植物（后几帧还插在玻璃杯里养着），
没有大蕉，也没有任何捣泥动作。

原因不是模型不行，是**词有歧义**：英语 `plantain` 既是大蕉，
也是车前草（Plantago，一种阔叶杂草）。模型选了杂草义。

**这是一类新的缺陷，读 prompt 看不出来，只有看视频才知道。**
它和"末态定不定义得出来"那条判据是正交的——末态很明确，只是渲染的东西不对。
**宾语被渲染成别的东西的格子，对体态问题零信息量，是缺陷不是发现。**

已加 `AMBIGUOUS_NOUNS` 过滤（`plantain` 已证实、`date` 近乎必然），
回归测试加了 `MUST_BE_UNUSABLE`。重建后生成子集仍是 37 个 item。

**剩下 4 个待筛查的**，都在强烹饪语境里，不猜，各跑一个视频看：

| item | 组合 | 风险 |
|---|---|---|
| 4 | `blending` + `kiwi` | 鸟 / 新西兰人 |
| 17 | `zesting` + `lime` | 石灰 |
| 31 | `squeezing` + `lime` | 石灰 |
| 32 | `frying` + `squash` | 壁球 / 挤压动词 |

约 14 分钟。

## 现在的整体判断

三轮下来，这个设计**测得动东西**，但**信噪比比我上一轮说的低**。
`result` 那个漂亮的差异要等除以 paraphrase 基线之后才知道剩多少。

这不是坏消息——这正是双锚存在的意义，而且是在烧掉 9 天算力**之前**发现的。
真正的坏消息会是：全量跑完才发现没有基线可比。

# 第四轮：全 37 个 item 的 `prog` 筛查

每个 item 一条 `prog`、seed 42、4 帧。只判两件事：**渲染出的是不是那个宾语**、
**那个动作有没有被执行**。不涉及体态。

## 先扣掉两条：一个 resume bug

item 0（`rolling`+`crust`）显示的是擦胡萝卜，item 1（`zesting`+`grapefruit`）
显示的是车前草。**这两条是旧视频**——屏蔽 `plantain`/`date` 后 item 重新编号，
而磁盘上的文件仍是旧编号，续跑按 `(item, condition, seed)` 匹配就把它们当成完成了。

已修：manifest 里本来就存了 prompt，现在 resume 会比对 prompt，不一致就重生成并打印出来。
**下面的统计基于其余 35 条。**

## 宾语：大体没问题

| | 数量 |
|---|---|
| 明确正确 | 27 |
| 存疑 | 4（`shallot` 像小西兰花、`zucchini` 渲染成圆形、`grapefruit` 像橙子、`pastry` 渲染成烤好的千层）|
| **明确错误** | **4** |

四个明确错误：

| item | 组合 | 渲染成了 |
|---|---|---|
| 7 | `sauteing` + `crust` | 一堆**烤好的面包卷**，不是派皮生坯 |
| 12 | `browning` + `shallot` | 一团焦黑，认不出是什么 |
| 13 | `mashing` + `radish` | **叶菜**——萝卜缨，不是萝卜根 |
| 36 | `grilling` + `beet` | 画面里全是青菜，看不到甜菜 |

三个歧义名词的筛查结果：**`kiwi` 渲染成水果、`lime` 渲染成青柠、`squash` 渲染成南瓜属蔬菜，
三个都没问题，不用屏蔽。** 猜是对的，但值得实测。

`crust` 和 `pastry` 则出了问题：两者都是面团阶段的词，模型却渲染成成品。
这和当初 `rolling a biscuit` 是同一类现象，只是这次不在我们的词表里——
**是模型的偏好，不是我们的错**，但结果同样不可用。

## 真正的问题：动作大多没有被执行

| | 数量 | 占比 |
|---|---|---|
| 动作明确被执行 | 8 | 23% |
| 部分/存疑 | 5 | 14% |
| **完全没有执行** | **22** | **63%** |

大多数视频渲染的是**"关于某个食材的场景"**，不是**"某人在对它做某事"**：
整只菠萝杵在台面上不动（`blending`）、一块蛋糕静静放着（`coating`）、
市场摊位上一堆胡萝卜（`frying`）。

**这对本设计是要害问题：`prog` 里连过程都没有，问"过程有没有走到完成"就无从谈起。**

## 两条能解释它的规律

### 1. 场景：`at a market stall` 全线失败

| 场景 | item 数 | 动作被执行 |
|---|---|---|
| `at a market stall` | 9 | **0**（1 条部分） |
| 三个厨房场景合计 | 26 | 12（46%） |

市场摊位是**陈列食材**的地方，不是加工食材的地方——场景先验和动作直接冲突。
**`SCENES` 里去掉 `at a market stall`**，一次性去掉 9 个近乎必然失败的 item。

### 2. 动词：有没有专属工具

八个成功的：`whipping`（打蛋器）、`sauteing`（平底锅）、`grilling`（夹子+炭痕）、
`squeezing`（榨汁器）、`grating`（刨丝器）、`roasting`（烤盘）、`rolling`（擀面杖）、
`crushing`（刀背）——**全都有一件视觉上独特的器具**。

失败的那些，动词的器具要么通用要么根本没出现：`blending` 从头到尾没有搅拌机、
`mashing` 没有捣泥器、`shredding` / `chopping` / `mincing` 只有一把刀。

**模型渲染的是器具，不是动作。** 这句话本身是个可报告的观察，
而且横跨三个体态类（成功项里 IT / DA / activity 都有），不是体态类效应。

## 这对论文意味着什么

**可以改成两级结果，而不是当作数据缺陷：**

1. **第一级**：模型到底会不会渲染这个事件——**动作执行率**。
   这一级本身就是结果，而且比"体态编码"更基础、更容易被别的工作引用。
2. **第二级**：在确实渲染了事件的 item 里，culmination 有没有被编码。

筛选依据只用 `prog`（基线条件），对体态对比是外生的，
所以"只在渲染成功的 item 上做体态分析"是可辩护的，不是挑数据。

这样 63% 的失败不是浪费，是第一级的结果。
